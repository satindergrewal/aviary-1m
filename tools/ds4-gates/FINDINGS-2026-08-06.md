## 1. `-np > 1` corrupts and DESTROYS KV — absolute offsets vs local ubatch indices

**Severity: highest.** It is not a corner case: it fires whenever the scheduler puts two sequences in
one batch, which under continuous batching is normal load.

**The mechanism.** The paged scheduler builds one batch (e.g. 29 tokens, 2 sequences,
`batch_offsets = [0,15]` — *absolute*). `llama_memory_hybrid::init_batch` then calls
`balloc.split_seq()`, which yields **one sequence per ubatch** (15 tokens, then 14), each **locally
indexed from 0**. The paged batch info is passed to each dispatch **unchanged**.

```
n_tokens=15 | batch_offs = 0 15 | batch_lens = 15 14    fine
n_tokens=14 | batch_offs = 0 15 | batch_lens = 15 14    CANNOT WORK
```

The kernel resolves a token's sequence with
`gtok >= batch_offsets[s] && gtok < batch_offsets[s]+batch_lens[s]`. With `gtok` local (0..13) and
offsets absolute, **every token matches `s=0`** and reads `block_table[0*max_blocks+bi]` — the other
sequence's blocks.

**Both halves are broken, and the write half destroys data.** The write kernels use
`write_slots[gtok]` with `gtok = tgpig[0]`, so the second sequence writes its KV **into the first
sequence's block**.

| | symptom |
|---|---|
| read side | a sequence returns the *other* sequence's answer (CROSSED) |
| write side | the victim's KV is overwritten → GARBAGE |

That explains the observed mix (GARBAGE ×2, CROSSED ×1): which one surfaces depends on how much was
clobbered before it was read.

**Call sites the fix must cover — FOUR on Metal, enumerated not recalled:**

| kernel | line | role |
|---|---|---|
| `kernel_paged_attn_f32` | 3193/3204/3392/3444 | read — measured broken |
| `kernel_paged_attn_write_f32` | 3063 | write |
| `kernel_paged_attn_write_q8_0` | 3005 | write |
| `kernel_paged_champ_mask` | 12850 | **mask** — opt-in `DS4P_METAL_CHAMP`, dormant, still needs it |

⚠ Fixing only the read leaves the destructive half and merely changes the symptom to GARBAGE.
⚠ Dormant is not fixed: the champ path becomes a latent trap for whoever enables it.

**Possibly cross-backend — READ-ONLY, NOT MEASURED.** The split is above the backend
(`llama-batch.cpp` names no backend), so every backend gets absolute offsets against a local Q.
CUDA (`pagedattn.cu:109`) and CPU (`ops.cpp:12250`) index `q[batch_offsets[seq_idx] + i]` directly —
they would read **past their own Q**. *Not claimed: that CUDA is broken.* A read-only hypothesis of
mine was refuted by measurement this same session; weight this below anything measured.

**Fix shape:** a contract decision — re-base the per-batch arrays per ubatch, or pass the ubatch's
absolute base to the kernels. It is one decision applied at four (or six) sites.

**Verify with:** `batch_offset_invariant_gate.sh` — checks `sum(batch_lens) == n_tokens` per
dispatch. FAILS 600/600 on the broken tree; **INCONCLUSIVE (exit 2), never PASS**, when no
multi-sequence dispatch occurs. Backend-agnostic by construction — it reads op args, not the kernel,
so **it runs on the box under CUDA unmodified.** That is the test that settles the cross-backend
question.

**Measured exclusions** (so nobody re-walks them): needs no history (fires on the first batch);
**not** slot-id reuse; **not** concurrent decode (a *verified* 4.04 s stagger is CLEAN 2/2 — the
scheduler co-batches only when work coincides, so two requests in flight ≠ one batch); packing is
exonerated (rows disjoint `511 510`, write_slots exactly `511*16` / `510*16`).

## 2. The paged cache drops every context and buffer it allocates

`llama_kv_cache_paged::init` allocates **eight** handles (counted in the code, not recalled — an
earlier version of this line said "six, of which four are locals" and was wrong):

| what | count | fate |
|---|---|---|
| pushed to `gpu_ctxs` / `gpu_bufs` | 2 sites | raw pointers, **class has NO destructor** |
| `ggml_init` locals | 3 | `ctx_cpu` (pool A), `ctx_gpu`, `ctx_cpu` (pool B) |
| `ggml_backend_alloc_ctx_tensors` locals | 3 | `buf_cpu` (A), `buf_gpu`, `buf_cpu` (B) |

The six locals are **never stored at all** — unreachable the moment `init` returns.

Every paged server trips upstream's residency-set assert at exit
(`ggml-metal-device.m:656`, *"you haven't deallocated all Metal resources before exiting"*); a static
server never does. **Fires with zero requests served**, so it is construction, not use.

Impact is larger than the abort: at process exit the OS reclaims everything, but any process that
creates and destroys a `llama_context` more than once — model reload, an embedding library, a test
harness — **leaks the entire KV pool per cycle**, with nothing to warn it.

**Fix:** hold them in `ggml_context_ptr` / `ggml_backend_buffer_ptr`. The types already exist in-tree
at `ggml/include/ggml-cpp.h:20`, and the pattern is used in **two** places already —
`llama-kv-cache.h:284` and `llama-adapter.h:36`. `llama-kv-cache-paged.h` does not yet include
`ggml-cpp.h`; that one include, two member type changes, and storing the six locals is the whole
change.
**Verify with:** `rset_leak_probe.sh` (5 one-factor arms; each marks itself UNUSABLE if its marker is
missing).
**DRAFT PATCH (unapplied):** `patches/DRAFT-defect2-raii-leak.patch` — 20 add / 4 del, targets the
**fork**. `git apply --check` passes. Not compile-tested, not run against the probe.

## 3. `/slots/N?action=save` reports success for a save that saved nothing

`{"n_saved":27,"n_written":716}` against an expected **864 KB** — 1236× short, HTTP 200.

**This is not a broken serialiser.** `server-context.cpp:3229` documents it: the paged path runs
`finish() → free_blocks()` and **returns blocks to the pool at request finish, by design** (*"holding
a finished sequence's blocks would fight the entire point of paging"*). The endpoint fires after the
completion returns, so `sequence_blocks.find(seq_id)` correctly misses and `state_write` correctly
writes nothing. Caller wired, serialiser complete, both working.

Self-drive CLEARED as a cause (`DS4P_PAGED_DRIVE=0` → byte-identical 716).

**Fix:** at the **endpoint** — refuse on the paged path, or route through the P1-5 finish-window
capture. ⚠ Not "make `state_write` work"; that fights the design.
**Verify with:** `state_serdes_gate.sh` (header carries the corrected diagnosis).
**DRAFT PATCHES (unapplied), a PAIR:** `patches/DRAFT-defect3-slotsave-refuse.patch` (18 add,
**fork**) + `patches/DRAFT-defect3-gate-arm-a.patch` (**gates repo**). ⚠ Applying either alone gives
a misleading red: the gate currently expects a *successful* save, so a correct refusal fails it until
its bar is inverted. Both `git apply --check` clean; neither compile-tested.

## Performance: the paged prefill penalty is entirely in the attention term

Four lengths, `n_predict=1`, both arms fit `t = a·n + b·n²` (max residual: static 0.2%, paged 0.9%):

| | linear `a` | quadratic `b` |
|---|---|---|
| static | 1.3567e-3 | 1.0223e-8 |
| paged | 1.3275e-3 | 8.8281e-8 |
| **paged/static** | **0.98× — identical** | **8.64×** |

Leave-one-out: quad ratio 8.61–8.71. The fitted curve predicts a **separate run's** 25743-token point
to 1.7%.

**Consequence: the scheduler, block tables and pool are EXONERATED** — per-token cost is identical.
Narrowed further to **per-key, not per-block** (`--kv-block-size` 8/16/32 spans 1.26× against a
measured 1.40× error bar; a per-block cost was predicted at ~4×).

**MMA is not the fix** — enabling it at D=256 is *slower* (12.00 s / 105.70 s vs scalar 7.27 s /
71.62 s), losing on occupancy: `nsg=1`, tile takes 29760 of 32768 bytes.

Independently corroborated by `metal_decode_wall`: decode is 1.17× (static 103.33 / paged 88.39
tok/s) — exactly what an identical linear term plus an 8.6× quadratic predicts at `n_tokens=1`.

**Correctness at length is fine:** 3/3 needle retrieval at 25.7K tokens matching static.
**Next lead, named and not run:** `DS4P_METAL_MMA_NOSTAGE_K` frees `KT*head_dim` = 16 KB at
KT=32/D=256 — the gap between `nsg=1` and `nsg=2/4`.

## Why these survived a suite of 29 scripts

Running the suite for the first time found **seven defects — six in the measuring apparatus.**

The one that mattered: `hybrid_paged_gate` runs `-np 2`, is a correctness gate, and **passed 4/4**
while the paged path was destroying KV — because it sends requests **sequentially**
(`for i in 0 1 2 3; do curl ...; done`, no `&`). One sequence in flight, every batch
single-sequence, bug dormant. **Flags are a claim; behaviour is the coverage.**

`lint_claimed_vs_entered.sh` now checks this statically (3 of 6 fail).
`coverage_census.sh` derives the suite composition, because the hardcoded count in `COVERAGE.md` went
stale within the hour.

**The rule that came out of it:** make every gate state what it does when it has measured nothing —
and make that something other than PASS.

## Recommended order (my call — overrule freely)

**#2 and #3 first** — cheap, safe, mechanical, proven causes, no design question.
**#1 last** — highest impact by a distance, but its fix *shape* is undecided until one measurement.

| | why now / why wait |
|---|---|
| **#2 leak** | RAII in one file; the correct pattern is already next door at `llama-kv-cache.h:284`. Changes ownership, not behaviour. Every paged run currently ends in an abort — noise in every gate log, and an instant blocker for any upstream submission. |
| **#3 slot-save** | A refusal at one endpoint. ⚠ Do **not** "make `state_write` work" — that fights the design. |
| **#1 `-np>1`** | Destroys KV under ordinary continuous batching, so `-np > 1` is unusable, not merely wrong. But the fix is a **contract decision** across four Metal sites and possibly CUDA/CPU. |

★ **Before choosing #1's fix shape, run `batch_offset_invariant_gate.sh` under CUDA on the box.**
No code changes; backend-agnostic by construction.

- CUDA **fails** it too → the fix belongs at the **batch-info level**; a per-kernel patch would be
  four fixes that drift apart.
- CUDA **passes** → Metal's scan is the outlier and a local fix is defensible.

A ~20-minute run that changes what the right fix *is*. Doing the cheap certain repairs while the
expensive uncertain one waits on a measurement is sequencing, not procrastination.

# ✅ 1c CLOSED BY MEASUREMENT — 2026-08-09

**1c was the paged cross-request corruption**, root-caused and fixed on 2026-08-08/09 (`6391c5e63`, fork
`ds4-ports`). The fingerprints match exactly:

| 1c, as characterised 2026-08-06 | the defect fixed 2026-08-09 |
|---|---|
| **requires a prior finished request** (WARM 7/12 corrupt, COLD 0/24) | request 1 is clean *because the `s_copy` buffer is zero on fresh allocation*; the request **after** one finishes reads leftover activation bytes |
| **prompt content irrelevant** | the trigger is chunk **geometry**, not content |
| 13 exclusions, two refuted fixes | the cause was in a subsystem none of them touched — an attention-only early return skipping the recurrent input |

## The verification, and why it needed three corrections first
`gemma4-26b-a4b-uncensored-1M-Q4_K_M` — **the model 1c was characterised on** — tip `4b7e0066c`, `-lv 5`,
WARM regime, 4 reps interleaved with order flip:

| arm | A | B | post | consume | verdict |
|---|---|---|---|---|---|
| paged ×4 | ok | ok | 4 | **630** | CLEAN |
| static ×4 | ok | ok | 4 | n/a | CLEAN |

⇒ **`consume=630` per paged rep** — the paged path is demonstrably live, so CLEAN is a real pass rather
than the vacuous one predicted. *Without that counter the two are indistinguishable.* (credit: Grok)

### Three attempts before a readable verdict
1. **`multislot_gate.sh` passed 12/12 and could not answer.** Its `probe()` is server-up → concurrent pair
   → server-down: **no prior finished request**, i.e. COLD by construction, and COLD was 0/24 even in the
   defect era. This file already warned that `content_diff_probe.sh` had exactly this hole.
2. **The first WARM gate voided itself** — `n_predict=24` on a reasoning model truncated arm A mid
   `<think>`, scoring **static 0/6 and paged 0/6**. *Static runs no paging: a dirty control means the gate
   is measuring itself.* It printed "1c REPRODUCES" and the control is the only reason that never left the
   box.
3. **The second WARM gate ran the wrong model** — Ornith, where the fix is established, not Gemma4 where
   1c lives. Clean, and scoped only to Ornith.

⇒ New gate: **`warm_multislot_gate.sh`** — prime (asserted) → concurrent pair → **third sequential
request**, the last of which measures *what the pair leaves behind*; a half no gate in this lane had ever
covered. Verdict is VOID if the static control is dirty **or** if the paged arm shows no consume events.

⚠ **Scope:** 4 reps, `-np 2`, one prompt pair, two models. **CLOSED-BY-MEASUREMENT ≠ "paged multi-slot is
proven."**
