## 1. SHIPPED mainline features

**Quantized KV: `-ctk/--cache-type-k`, `-ctv/--cache-type-v`**
- K-cache quantization: PR #4312 "llama : support quantum K cache" (ggerganov, MERGED 2023-12-06). https://github.com/ggml-org/llama.cpp/pull/4312
- Flash Attention: PR #5021 (ggerganov, MERGED 2024-04-30) https://github.com/ggml-org/llama.cpp/pull/5021 - prerequisite for quantized V. Enforcement is live on master at `src/llama-context.cpp:458-460`: `throw std::runtime_error("quantized V cache was requested, but this requires Flash Attention")`. Reason: the non-FA path stores V transposed and reads it with strided views that quantized blocks can't support; FA consumes V row-contiguously.
- Allowed types (long-standing set in `common/common.cpp` via `get_all_kv_cache_types()`): f32, f16, bf16, q8_0, q4_0, q4_1, iq4_nl, q5_0, q5_1.
- Per-layer cache-type: NOT in mainline (searched; nothing merged or open). Closest mechanisms: iSWA keeps two differently-sized caches for layer subsets (#13194), hybrid models simply have no KV on recurrent layers. Arch-specific trap: DeepSeek-V4 K-cache quantization produced garbage because Hadamard rotation forced the model off its sparse paths - issue #16331-style report #25382 (closed completed) + fix PR #25391 (closed unmerged), 2026-07-07.

**Context shift (StreamingLLM-like keep+shift)**
- Server-side: keeps `--keep` tokens, discards half the rest, then `llama_memory_seq_rm` + `seq_add` (position shift). Flags today: `--context-shift` / `--no-context-shift` (arg.cpp:1652).
- DEFAULT IS OFF since PR #15416 "server : disable context shift by default" (ggerganov, MERGED 2025-08-19). https://github.com/ggml-org/llama.cpp/pull/15416 - `common.h:572 bool ctx_shift = false`.
- Disabled automatically (verified on master source): (a) multimodal - `server-context.cpp:1217 "ctx_shift is not supported by multimodal"`; (b) whenever `llama_memory_can_shift()` is false - `llama-kv-cache.cpp:1278 get_can_shift()` returns false for LLM_ARCH_STEP35 ("per-layer RoPE dims; K-shift assumes a single global n_rot"), for `n_pos_per_embd() > 1` (mrope/VL models), and for any layer with `k_idx` tensors - comment: "shifting would leave k_idx stale". That last one means ALL DSA-indexer models (DeepSeek V3.2, GLM-5.x sparse path) cannot context-shift. iSWA caches only shift if base and SWA caches are equal size, i.e. effectively requires `--swa-full`. Recurrent `get_can_shift()` returns true (pos shift is trivial) but partial mid-sequence erase is unsupported, so shift/reuse degrade to full reprocess on recurrent/hybrid (see section 6).

**`--cache-reuse` (chunked prompt-cache reuse)**
- PR #9866 "server : reuse context chunks" (ggerganov, MERGED 2024-10-13). https://github.com/ggml-org/llama.cpp/pull/9866. After longest-common-prefix matching, KV chunks >= N tokens are kept and their positions shifted via the K-shift mechanism instead of recomputing. Requires `--cache-prompt`; inherits the can_shift restrictions above (so no reuse on DSA-indexer archs). Known gap: "cache-reuse not effective in qwen3-next" issue #18497 (closed) - it cannot work on recurrent state.

**SWA**
- iSWA: PR #13194 "kv-cache : add SWA support" (ggerganov, MERGED 2025-05-20). https://github.com/ggml-org/llama.cpp/pull/13194. Two internal unified caches (non-SWA + SWA layer subsets); SWA cache sized `PAD(n_swa*n_seq_max + n_batch)` and "automatically forgets/prunes old tokens" - that formula is the memory saving (window-sized instead of n_ctx-sized for SWA layers).
- `--swa-full` (default off, `common.h:573`): keep full-size SWA cache to retain advanced caching. ggerganov in the linked comment (issuecomment-2868343055): "Both the old cache (i.e. more memory usage, but with advanced caching supported) and the new cache (less memory with just last-prefix caching) will be supported."
- SWA checkpoints for branching: PR #15293 "server : add SWA checkpoints" (ggerganov, MERGED 2025-08-14). https://github.com/ggml-org/llama.cpp/pull/15293. Today generalized to `-ctxcp/--ctx-checkpoints` (alias `--swa-checkpoints`, default 32/slot) plus `-cms/--checkpoint-min-step`; hybrid checkpoint cadence via PR #20087 "Hybrid model cache: add --checkpoint-every-nb" (pwilkin, MERGED 2026-03-06).

**Attention sinks**
- Added with gpt-oss: PR #15091 (ggerganov, MERGED 2025-08-05) - sink term in `ggml_soft_max_ext` + FA. https://github.com/ggml-org/llama.cpp/pull/15091. ## 2. COMPUTE BUFFER at long context

- Mechanism (code-verified): `ggml_backend_sched` preallocates the WORST-CASE graph at context creation (`llama-context.cpp:656` carries a live TODO: "not sure if the following graph would be worst case for multi-stream KV caches"). Without FA, the f32 KQ matrix [n_kv, n_ubatch, n_head] dominates and scales with n_ctx * n_ubatch. With FA that tensor disappears, but the KQ mask [n_kv, n_ubatch] and per-ubatch activations still scale; `-ub` (and `-b`) scale the buffer roughly linearly, `-ctx` scales the mask/KV-dependent parts. Field measurement [field]: GLM-5.2 on 2x Pro 6000 = ~22.8 GiB compute buffer at 128K with `-ub 512`, OOM at 16K until `-ub 256`, while KV at 64K was only 1.6-3 GiB - compute buffer, not KV, is the practical context ceiling.
- Shrink work merged: PR #25370 "make all KQ masks f16 if FA is used, remove zero attention bias, remove raw_k repeats in DeepSeek V4" (fairydreaming, MERGED 2026-07-10) - halves mask memory. PR #14924 "CUDA: skip masked KV slices for all FA kernels" (MERGED 2025-07-30) - compute skip (speed, not allocation). Issue #25468 "DeepSeek-V4-Flash lightning-indexer materialises a ctx-proportional (4 GiB/layer) score buffer" (closed completed 2026-07-08) - fixed via the fused indexer op path.
- Auto-fit: PR #16653 "llama: automatically set parameters not set by the user in such a way that maximizes GPU utilization" (JohannesGaessler, MERGED 2025-12-15) = the `-fit` machinery (default ON, `common.h:478`, `fit_params_min_ctx = 4096`); CPU-only fit #21568 (MERGED 2026-04-18); long fix series (#18233, #18354, #18679, #19070, #23282).
- Open OOM/over-reservation issues where weights+KV fit but compute buffer does not: #26038 "Excessive compute buffer reservation in MTP draft context on ROCm HIP unnecessarily reduces fitted context size" (OPEN 2026-07-23); #25408 "fitting params to memory overallocates speculative context when ctx-size is unspecified" (OPEN) + fix PR #25465 (open); #24967 GGML_ASSERT n_outputs_max (open). Crash-class at long ctx: #23574 "GLM 5.x crashes/gibberish with high ubatch and long prompts" (closed) root-caused to KQ-mask offset INTEGER OVERFLOW in the FA MMA kernel, fixed by PR #23610 (MERGED 2026-05-28).
- Observability: #26129 (open FR: expose per-device weights/context/compute usage) + PR #26130 (open, /metrics + GET /memory).
- No mainline mechanism caps attention compute-buffer size directly (ik's `-amb` has no mainline equivalent).

## 6. HYBRID / LINEAR-ATTENTION models

- Storage model (master, verified): attention layers use the regular KV cache; recurrent layers store fixed-size per-seq state tensors (r_l conv + s_l ssm) in `llama-memory-recurrent.cpp`; hybrids combine both via `llama-memory-hybrid.cpp` (and `llama-memory-hybrid-iswa.cpp` for hybrid+SWA). State size is independent of context length - which is why hybrid KV stays tiny at 1M (field math: Nemotron-3 with 8 attention layers = ~8.6 GB KV at 1M ctx [field]).
- Arch PRs: Mamba #5328 (MERGED 2024-03-08, compilade); RWKV6 #8980 (2024-09-01, MollySophia); RWKV7 #12412 (2025-03-17, MollySophia); Mamba-2 #9126 (2025-07-02, compilade); Jamba #7531 (2025-07-09, compilade); Qwen3-Next #16095 (2025-11-28, pwilkin); Kimi-Linear #18755 "Kimi-Linear support (backend agnostic + MLA KV cache)" (MERGED 2026-02-06; chunk-size fix #19827 MERGED 2026-03-05; FR #16930; rejected earlier attempt #17592); Qwen3.5/3.6 hybrid family (landed ~2026-02-24, per the day-0 issue wave #19863-#19906; SSM-param fixes #23178/#23179, trunk-only-GGUF fix #25024, eagle3 #24593 MERGED 2026-06-19); Nemotron family (Nano-3 Omni convert #22481 MERGED 2026-04-28; Nemotron-3-Puzzle-75B MTP #25444 OPEN); MiniCPM-SALA FR #22617 (closed).
- Perf gaps: #18102 (OPEN) CUDA Delta-Net for Qwen3-Next; GDN CUDA optimizations #20448/#20449 (closed unmerged); #19345 "40% slower than vLLM on Qwen Coder Next" (closed).
- Context-shift/checkpoint limitations: recurrent state cannot be partially erased or rolled back, so context shift and `--cache-reuse` do not work (#18497 closed: "cache-reuse not effective in qwen3-next"); any prompt divergence forces full reprocess - live bug #22746 (OPEN): "Qwen 3.6 27B forcing full prompt re-processing due to lack of cache data". Mitigation = context checkpoints (#15293 + #16391 + #20087): each checkpoint copies the full recurrent state (+SWA window) into host RAM per slot; server logs per-checkpoint MiB and evicts by count (default 32/slot) and min spacing. Open/adjacent: #24891 (checkpoint invalidation after tool calls), #24028 (persist checkpoints to disk), #20428 (closed unmerged multi-turn reuse fix), #21173 (closed FR: slot save/restore for hybrid/Qwen3.5 + multimodal), #24785 (OPEN state shrink/expand), #25840 (OPEN: hybrid Qwen3.6-35B `-np 3` decode drops 4.4x for non-contiguous slot pairs). ik equivalent: DeepSeek V4 checkpoints PR #2195 (OPEN 2026-07-27).
- Maximizing context on hybrids: nothing dedicated upstream beyond `--fit`; the KV-lite property does the work (see finding 3). ngxson explicitly frames hybrids as the DSA alternative: "Kimi-Linear/Qwen3.5 addressed the same problem by moving to a new hybrid arch" (#20363).

## The 5 most useful findings for maximizing context on fixed VRAM today

1. The binding ceiling at 128K+ is the worst-case COMPUTE buffer, not KV: it scales with n_ctx x n_ubatch, so `-ub 256` (plus FA + `--fit`, default-on since #16653) buys more context than any KV quant; ik's `-amb` is the only flag anywhere that caps it directly.
2. FA + `q8_0/q5_1/iq4_nl` KV (V-quant requires FA, llama-context.cpp:458) remains the cheapest 2-4x KV cut, but is arch-dependent: DSV4's K-quant garbage (#25382) shows sparse-attention archs can break under rotated K quantization.
3. Architecture beats caching: iSWA (window-sized SWA cache, keep `--swa-full` off) and hybrid SSM models (KV only on the few attention layers; Nemotron-3 = 8.6 GB KV at 1M) are the only shipped order-of-magnitude KV reductions; the cost is broken shift/reuse, patched by `--ctx-checkpoints`.
4. DSA sparse attention is finally real in mainline (DSV3.2 #23346 since 05-29, GLM-5.2 #25407 since 07-24, MiniMax-M3 MSA #24908 since 07-26) - it flattens decode COST at depth but saves zero KV memory, disables context-shift/cache-reuse (k_idx), and its fast CUDA kernel (#25917) plus fused top-k (ik has them; mainline does not) are still pending - ik_llama.cpp is currently ahead on DSA performance.
5. Paged KV does not exist in mainline and is socially blocked (#22569 open-but-rejected-in-spirit, #17579 closed; core maintainers silent): on fixed VRAM the practical multi-request levers are `--kv-unified` (default; per-seq cap = full n_ctx), `--cache-ram` host prompt-cache + checkpoints - and vLLM-class paging requires matiaslin's CUDA-only fork or leaving llama.cpp.
